## Introduction

Take a look at these passwords:

```
vfccjdbrpfntqybrk.lf
aeylfvtynfkmystbccktljdfybz
bnjvtufkjdbhecyfzbyatrwbjyyfz
tybnyjhfrtnyfzhflbjkjrfwbjyyfz
```
They look randomly generated to you. To me they're Russian passwords, or more precisely Russian transliteration. So how did I crack them, and what do they actually mean?


## What is Transliteration?
Transliteration *is not* the same as *translation*. When you translate a word into English, you change its **meaning**. When you transliterate it, you keep the meaning and only change how it's **written or pronounced** using the English alphabet.

[![Russian-keyboard](https://m.media-amazon.com/images/I/61fg0enBGjL._AC_UF1000,1000_QL80_.jpg)](https://m.media-amazon.com/images/I/61fg0enBGjL._AC_UF1000,1000_QL80_.jpg)

This is a Russian QWERTY keyboard, with both Russian and English letters on each key. Map every Russian letter to the English letter that shares its key, and you've transliterated Russian into English.

For example, `Ф` sits on the same key as `A`, so it maps to `A`. `Ы` maps to `S`, `B` maps to `D`, and so on. Doing this by hand is tedious, so I let `sed` handle it:

## Let's Transliterate Russian Passwords
The script works. Now, how do we find Russian passwords to feed it? Maybe there's a convenient `rockyou-russian.txt` lying around somewhere?

As far as I've searched, no. Most sites only accept UTF-8 into their database, so any leaked "Russian" password is just an English word, a Russian phrase already transliterated, or something similar. We need another source.

## Wikidumps
The Wikimedia Foundation gives us access to its database, so we can [download Russian Wikipedia articles](https://dumps.wikimedia.org/ruwiki/), strip the digits and punctuation, lowercase everything, and run it through `translit.sed`. A few other sources work too:
- [ruwikinews](https://dumps.wikimedia.org/ruwikinews/)
- [ruwiktionary](https://dumps.wikimedia.org/ruwiktionary/)

To strip digits and punctuation and lowercase the source file, we can use `tr`:
```console title="removing digits, punctuation, and lower casing all characters"
$ cat source.dict | tr -d '[:digit]' | tr -d '[:punct]' | tr '[:upper:]' '[:lower]' > prepared-source.dict
```
<details>
  <summary>Explain this</summary>

- `cat` reads our file and outputs it to `stdout`  
- `|` pipes our `stdout` to the next binary (in this case it's `tr`)  
- `tr -d '[:digit]'` removes digits  
- `tr -d '[:digit]'` removes punctuation  
- `tr '[:upper:]' '[:lower]'` lowercases uppercase characters  
- `>` streams the result to a file  

</details>

Before transliterating the prepared file, we need to deduplicate it. I use [nil0x42/duplicut](https://github.com/nil0x42/duplicut) for this:
```console title="installing duplicut"
$ git clone https://github.com/nil0x42/duplicut 
$ cd duplicut/ && make                          
```
```console title="duplicating prepared source"
$ ./duplicut -o deduplicated-prepared-source.dict prepared-source.dict
```

Now we can transliterate:
```console title="translitering with translit.sed"
$ cat deduplicated-prepared-source.dict | sed -f translit.sed > transliterated.dict
```

Transliteration can collapse different Russian words onto the same output, so deduplicate one more time:

```console title="duplication"
$ ./duplicut -o deduplicated-transliterated.dict transliterated.dict
```

That's the wordlist. Now we can hand it to Hashcat and start cracking.

## Using Combinator Mode to Crack Long Transliterated Passwords
I cracked every password at the top of this post with Hashcat's combinator mode. It takes two wordlists and glues each word from the first onto each word from the second.

For example, if `chickennoodle` is in `file1.txt` and `dumpling` is in `file2.txt`, then:
```console title="hashcat combinator mode"
$ hashcat -a 1 --stdout file1.txt file2.txt
chickennoodledumpling
...
```
would produce the combined password above. The trick is to pass `deduplicated-transliterated.dict` as both wordlists, so it gets combined with itself:
```console title="hashcat combinator mode"
$ hashcat -a 1 --stdout deduplicated-transliterated.dict deduplicated-transliterated.dict
vfccjdbrpfntqybrk.lf
aeylfvtynfkmystbccktljdfybz
bnjvtufkjdbhecyfzbyatrwbjyyfz
tybnyjhfrtnyfzhflbjkjrfwbjyyfz
...
```

## Conclusion
Nothing in computers is *truly* random, and passwords are no exception. The same idea extends to other techniques for generating plausible-looking strings, which can crack even trickier passwords. So the takeaway is simple: use a long password that mixes upper and lower case, symbols, and digits. `4tYb!n6y$%/Jh)f.r3T-n/|yF?zh8*flb09Jkj!RFw[bjyYfZ!26&?` is a far harder target than `tybnyjhfrtnyfzhflbjkjrfwbjyyfz`. Use a password manager like Bitwarden, rotate your passwords when you can, and sign up for breach alerts from [Have I Been Pwned](https://haveibeenpwned.com/NotifyMe).

As always, happy cracking. Don't use any of this for malicious purposes, obviously.
